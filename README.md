# Service Studio — магазин услуг с серверным API

Учебное веб-приложение на React + Vite с отдельным сервером Express и базой данных PostgreSQL. Структура и запуск соответствуют презентации «Работа с данными»: клиент работает на порту `5173`, API — на порту `3001`, сервер подключается к PostgreSQL, а frontend обращается к серверу через HTTP API и получает JSON.

## 1. Структура проекта

```text
service_store_project/
├── database/
│   └── schema.sql             # создание таблиц и связей PostgreSQL
├── backend/
│   ├── scripts/seed.js        # начальное заполнение БД
│   ├── db.js                  # подключение к PostgreSQL через pg
│   ├── middleware.js          # проверка токена и роли администратора
│   ├── server.js              # Express API, CRUD и бизнес-логика
│   ├── package.json
│   └── .env.example           # пример настроек сервера
├── src/
│   ├── api/client.js          # запросы frontend к API
│   ├── components/            # карточка услуги и общая шапка
│   ├── context/AppContext.jsx # общая корзина, пользователь и тема
│   ├── pages/                 # каталог, корзина, вход, кабинет, админ-панель
│   ├── App.jsx
│   ├── main.jsx
│   └── styles.css
├── package.json
└── vite.config.js
```

## 2. Таблицы базы данных

- `Roles` — роли `admin` и `customer`.
- `Users` — пользователи, электронная почта, хеш пароля и роль.
- `Categories` — категории услуг.
- `Services` — название, описание, длительность, цена, категория и общая скидка.
- `UserCoupons` — персональный купон пользователя. Поле `user_id` уникальное, поэтому пользователю соответствует не более одного купона.
- `Appointments` — записи пользователя на услуги, количество, цена и применённые скидки.
- `Payments` — платёж для каждой созданной записи. В учебном проекте создаётся со статусом `pending`; реальное списание денежных средств не производится.

Требуемые таблицы `Users`, `Roles`, `Services`, `Appointments` и `Payments` присутствуют. Дополнительные `Categories` и `UserCoupons` реализуют фильтрацию и систему скидок.

## 3. Установка PostgreSQL и создание базы

Убедитесь, что PostgreSQL установлен и запущен. Создайте базу данных с именем `service_store`:

```sql
CREATE DATABASE service_store;
```

После создания базы откройте терминал в корне проекта и выполните:

```bash
psql -U postgres -d service_store -f database/schema.sql
```

Если у вас другой пользователь PostgreSQL, укажите его вместо `postgres`.

## 4. Настройка и запуск backend

Откройте отдельный терминал:

```bash
cd backend
```

Создайте файл `.env` на основе примера:

**Windows PowerShell:**
```powershell
Copy-Item .env.example .env
notepad .env
```

**macOS / Linux:**
```bash
cp .env.example .env
```

В `.env` укажите свои данные PostgreSQL. Например:

```env
PG_HOST=localhost
PG_USER=postgres
PG_PASSWORD=ваш_пароль_postgresql
PG_DATABASE=service_store
PG_PORT=5432
PORT=3001
JWT_SECRET=замените_на_свою_секретную_строку
```

Установите зависимости, заполните таблицы демонстрационными данными и запустите API:

```bash
npm install
npm run seed
npm run dev
```

После запуска API будет доступен по адресу `http://localhost:3001`. Проверить соединение с базой можно по адресу `http://localhost:3001/api/health`.

## 5. Запуск frontend

Откройте **второй** терминал в корне проекта `service_store_project`:

```bash
npm install
npm run dev
```

Откройте адрес Vite: `http://localhost:5173`.

В `vite.config.js` настроен proxy `/api` на `http://localhost:3001`, а сервер Express также включает CORS. Поэтому запросы frontend направляются на серверный API, а не выполняются напрямую к PostgreSQL.

## 6. Демонстрационные учётные записи

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@demo.ru` | `Admin123!` |
| Пользователь | `client@demo.ru` | `Client123!` |

У демонстрационного пользователя изначально есть персональный купон `WELCOME-5` на 5%. Администратор может заменить его другим видом купона.

## 7. Реализованная функциональность

### Каталог услуг
- Получение услуг и категорий через API.
- Название, описание, длительность и цена услуги.
- Отображение общей скидки и прежней цены.
- Добавление услуг в корзину.
- Поиск по каталогу.
- Фильтрация через отдельный `aside` слева от каталога: для каждой категории используется checkbox.
- Категории не заданы статическим списком: frontend получает их с `/api/categories`. Новая категория, добавленная администратором, возвращается API и автоматически появляется в боковой панели.

В начальном наборе ровно 10 услуг, у 3 из них установлена общая скидка (30%).

### Корзина
- Добавление услуги и увеличение количества.
- Изменение количества и удаление услуги.
- Автоматический подсчёт стоимости.
- Применение персонального купона пользователя.
- Создание записей через API. После запроса сервер повторно получает цены и скидки из БД, создаёт записи в `Appointments` и связанные платежи в `Payments`.

### Авторизация
- Форма с полями email и пароль.
- Проверка заполнения полей и формата email.
- Проверка пароля на сервере через bcrypt.
- JWT-токен для защищённых запросов.
- Разграничение прав пользователя и администратора.

### Панель администратора
- Добавление категорий.
- Добавление услуг.
- Назначение или изменение общей скидки на конкретную услугу.
- Выдача одного персонального купона пользователю: приветственный 5%, постоянный клиент 10% или персональный 15%.
- Список пользователей и уже назначенных им купонов.

### Загрузка и ошибки
- Отображаются состояния загрузки при запросах к API.
- Ошибки сервера, авторизации и подключения к API выводятся в интерфейсе.
- При недоступности backend каталог показывает сообщение и кнопку повторного запроса.

## 8. Основные адреса API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка API и БД |
| GET | `/api/categories` | Получение категорий |
| POST | `/api/categories` | Добавление категории (admin) |
| GET | `/api/services` | Получение каталога услуг |
| POST | `/api/services` | Добавление услуги (admin) |
| PATCH | `/api/services/:id/discount` | Изменение скидки услуги (admin) |
| POST | `/api/auth/login` | Авторизация |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/admin/users` | Список пользователей (admin) |
| PUT | `/api/admin/users/:id/coupon` | Выдача персонального купона (admin) |
| GET | `/api/appointments/my` | Записи текущего пользователя |
| POST | `/api/appointments` | Создание записей и платежей из корзины |

## 9. Проверка работы

1. Запустите PostgreSQL, затем backend и frontend в двух терминалах.
2. Откройте каталог и убедитесь, что данные загружены из API.
3. Выберите одну или несколько категорий checkbox слева: список услуг должен измениться.
4. Добавьте несколько услуг, откройте корзину и поменяйте количество.
5. Войдите как `client@demo.ru`, чтобы увидеть персональный купон и проверить перерасчёт суммы.
6. Создайте запись и откройте личный кабинет: запись появится в истории со статусом платежа «Ожидает оплаты».
7. Войдите как администратор. Добавьте категорию и проверьте её появление в каталоге, добавьте услугу, измените скидку и выдайте пользователю другой тип купона.

> Это учебный проект. Платёжная запись сохраняется в базе со статусом `pending`, интеграции с платёжным провайдером нет.
