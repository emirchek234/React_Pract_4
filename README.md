# Service Studio — веб-приложение магазина услуг

Учебный проект на React + Vite, Node.js + Express и PostgreSQL.

## Возможности

- каталог услуг с категориями, фотографиями, длительностью, ценой, скидками и остатками на складе;
- просмотр фотографии в перечне услуг админ-панели, предпросмотр при редактировании и отдельное удаление изображения;
- постоянная системная категория «Без категории»: её нельзя переименовать или удалить, а услуги из удалённых категорий автоматически перемещаются туда;
- регистрация, вход, выход, восстановление пароля с одноразовым кодом по email;
- отдельная серверная корзина каждого пользователя и локальная корзина гостя;
- оформление заказа с адресом и датой доставки, снимком всех позиций, количествами и применённым купоном;
- личный кабинет: редактирование контактов и адреса, смена пароля, история заказов;
- отзывы с оценками и проверкой текста;
- админ-панель с модальными окнами и поиском: категории, услуги, заказы, пользователи и купоны;
- отдельная страница модерации отзывов;
- две роли: admin и customer. Создать администратора через публичную регистрацию нельзя.

## 1. Подготовка PostgreSQL

Создайте базу данных:

```sql
CREATE DATABASE service_store;
```

Для **новой базы** выполните файл `database/schema.sql` в базе `service_store`.

Для базы, которая уже использовалась с предыдущей версией Service Studio, выполните миграцию:

```bash
cd backend
npm run migrate
```

Миграции `003_extended_store.sql` и `004_permanent_uncategorized.sql` добавляют серверную корзину, заказы, снимки позиций, отзывы, остатки, телефон и адрес пользователя, а также таблицу кодов сброса пароля. Она также объединяет старые категории, отличающиеся регистром или пробелами, предварительно перенося связанные услуги в сохранённую категорию. Миграция 004 дополнительно гарантирует наличие системной категории «Без категории». Старые `Appointments` и `Payments` не удаляются.

## 2. Настройка сервера

Скопируйте `backend/.env.example` в `backend/.env` и укажите параметры PostgreSQL и свой `JWT_SECRET`.

Для отправки кодов сброса пароля заполните SMTP-поля. Для Gmail обычно используется сервер `smtp.gmail.com`, порт `587`, STARTTLS и пароль приложения. Не указывайте основной пароль от почты. Для Gmail включите двухэтапную аутентификацию и создайте пароль приложения. Пример параметров для Gmail: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_SECURE=false`; для SSL-подключения обычно используют порт `465` и `SMTP_SECURE=true`. Если SMTP не настроен, в режиме разработки одноразовый код выводится в консоль backend; в production код не возвращается пользователю.

Установите зависимости и запустите API:

```bash
cd backend
npm install
npm run migrate   # только для уже существующей БД; для новой примените schema.sql
npm run seed
npm run dev
```

Демо-аккаунты:

- Администратор: `admin@demo.ru` / `Admin123!`
- Пользователь: `client@demo.ru` / `Client123!`

Это демонстрационные данные для локальной проверки. Перед реальным развёртыванием замените пароли и секреты.

## 3. Запуск frontend

В новом терминале из корневой папки проекта:

```bash
npm install
npm run dev
```

Откройте адрес Vite, обычно `http://localhost:5173`. Frontend проксирует `/api` и `/uploads` на сервер `http://localhost:3001`.

## Важные замечания

- Корзина зарегистрированного пользователя хранится в PostgreSQL. После выхода она не удаляется и снова загрузится при следующем входе этого пользователя.
- Гостевая корзина хранится локально и переносится в серверную после входа/регистрации.
- Заказ оформляется целиком в транзакции: проверяется наличие, записываются все позиции, уменьшаются остатки, очищается серверная корзина.
- Адрес, введённый при оформлении, становится адресом по умолчанию и отображается в личном кабинете.
- Удаление категории переводит её услуги в «Без категории». Если категорию не выбрали при создании услуги, используется та же системная категория.
- Услуги из каталога удаляются мягко, чтобы не ломать историю заказов и отзывы.
- Статус заказа меняется администратором в модальном окне «Заказы».
- В проекте реализована учебная фильтрация ненормативной лексики: нормализация учитывает регистр, разделители, частые замены символов и латинскую транслитерацию. Для реального коммерческого сервиса такую модерацию следует дополнить специализированным словарём/модерацией.
